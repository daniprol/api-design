APIs are now the main way data leaves a company, which makes them the main way data **leaks**. Many of the biggest breaches of the last decade weren't exotic hacks; they were APIs that answered questions they should have refused. Security isn't a layer you add at the end; it's part of the design.

## Two questions, in order

1. **Authentication**: _Who are you?_ → fails with <Status code={401} />
2. **Authorization**: _Are you allowed to do this, to this specific thing?_ → fails with <Status code={403} /> (or <Status code={404} /> to hide existence)

```http
GET /orders/42                                  → 401 + WWW-Authenticate: Bearer
GET /orders/42  Authorization: Bearer <token>   → 200 (if it's yours) / 404 (if not)
```

## OAuth 2.0 bearer tokens

The standard way to protect HTTP APIs: the client gets an **access token** from an authorization server and sends it with each request.

```http
GET /orders
Authorization: Bearer eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9…
```

The token says **who** (a user or a service) and **what they may do**: its **scopes** (a.k.a. permissions).

## Scopes: least privilege, good names

A scope is a named permission. Design them from the API's point of view, coarse enough to be manageable and fine enough to grant only what's needed:

```text
orders.read           read orders
orders.write          create/modify orders
orders.refunds.write  issue refunds (a separate, more sensitive power)
```

A reporting dashboard gets `orders.read`. Only the support tool gets `orders.refunds.write`.

```python
from fastapi import Security
from fastapi.security import OAuth2AuthorizationCodeBearer, SecurityScopes

oauth2 = OAuth2AuthorizationCodeBearer(
    authorizationUrl="https://auth.example.com/authorize",
    tokenUrl="https://auth.example.com/token",
    scopes={"orders.read": "Read orders", "orders.write": "Create and modify orders"},
)

def current_principal(security_scopes: SecurityScopes, token: str = Depends(oauth2)) -> Principal:
    claims = verify_jwt(token)  # signature, issuer, audience, expiry!
    if claims is None:
        raise HTTPException(401, headers={"WWW-Authenticate": "Bearer"})
    missing = set(security_scopes.scopes) - set(claims["scope"].split())
    if missing:
        raise HTTPException(403, f"Missing scope(s): {', '.join(missing)}")
    return Principal(id=claims["sub"], scopes=claims["scope"].split())

@app.get("/orders/{order_id}")
def get_order(order_id: str, me: Principal = Security(current_principal, scopes=["orders.read"])):
    order = repo.get(order_id)
    if order is None or order.customer_id != me.id:  # object-level check!
        raise HTTPException(404)
    return order
```

<TabItem label="Django" icon="seti:python">

```python
from rest_framework.permissions import BasePermission

class HasScope(BasePermission):
    """Use as: permission_classes = [HasScope.of("orders.read")]"""
    required: set[str] = set()

    @classmethod
    def of(cls, *scopes):
        return type("HasScope", (cls,), {"required": set(scopes)})

    def has_permission(self, request, view):  # 401 if no token, 403 if missing scope
        token_scopes = set(getattr(request.auth, "scopes", []))
        return self.required <= token_scopes

class IsOwner(BasePermission):
    def has_object_permission(self, request, view, obj):
        return obj.customer_id == request.user.id

class OrderViewSet(viewsets.ReadOnlyModelViewSet):
    serializer_class = OrderSerializer
    permission_classes = [HasScope.of("orders.read"), IsOwner]

    def get_queryset(self):  # defense in depth: only ever query the caller's orders
        return Order.objects.filter(customer_id=self.request.user.id)
```

<TabItem label="Hono" icon="seti:typescript">

```ts
import { jwk } from "hono/jwk";
import { createMiddleware } from "hono/factory";

// Verifies signature + expiry → 401 if invalid
app.use("/orders/*", jwk({ jwks_uri: "https://auth.example.com/.well-known/jwks.json" }));
// …and check it was issued by YOUR auth server, for THIS API (iss/aud)
app.use("/orders/*", async (c, next) => {
  const { iss, aud } = c.get("jwtPayload");
  const audiences = Array.isArray(aud) ? aud : [aud];
  if (iss !== "https://auth.example.com" || !audiences.includes("orders-api")) {
    return c.json({ title: "Token not valid for this API" }, 401);
  }
  await next();
});

const requireScope = (...needed: string[]) =>
  createMiddleware(async (c, next) => {
    const granted = new Set(String(c.get("jwtPayload").scope ?? "").split(" "));
    const missing = needed.filter((s) => !granted.has(s));
    if (missing.length) return c.json({ title: `Missing scope(s): ${missing.join(", ")}` }, 403);
    await next();
  });

app.get("/orders/:id", requireScope("orders.read"), async (c) => {
  const order = await repo.get(c.req.param("id"));
  if (!order || order.customerId !== c.get("jwtPayload").sub) return c.notFound(); // object-level check
  return c.json(order);
});
```

## The usual suspects

The **OWASP API Security Top 10** lists the most common API vulnerabilities. The top ones are design problems, not crypto problems:

| Risk                                       | In plain words                                                         | Defence                                              |
| ------------------------------------------ | ---------------------------------------------------------------------- | ---------------------------------------------------- |
| Broken Object Level Authorization (BOLA)   | Change `/orders/42` to `/orders/43`, see someone else's order          | Check ownership on **every** object access           |
| Broken Authentication                      | Weak tokens, no expiry, credential stuffing                            | Standard OAuth/OIDC, short-lived tokens, rate limits |
| Broken Object Property Level Authorization | Client sets `"is_admin": true` in a PATCH, or sees fields it shouldn't | Explicit allow-lists for input and output fields     |
| Unrestricted Resource Consumption          | `?limit=1000000`, huge uploads                                         | Max limits, pagination, rate limiting                |

## Secrets and transport

- **HTTPS only.** No exceptions, including internal traffic where possible.
- **Never put secrets in URLs** (`?api_key=…`): URLs end up in logs, browser history and `Referer` headers. Use the `Authorization` header.
- Short-lived access tokens; rotate API keys; never log tokens.

<Story kind="war-story" title="The 2019 Facebook phone-number scraping">

Attackers abused a contact-import feature, which let you find friends by phone number, to match phone numbers to Facebook profiles at scale. The resulting dataset of more than 500 million users was published in 2021. No password was stolen; an API simply answered a question millions of times without asking "should this caller be allowed to ask this, this often?" Rate limits and abuse detection are security features.

</Story>

<Story kind="war-story" title="Optus, 2022">

In September 2022, Australian telco Optus suffered a breach affecting about 10 million customers. Reports at the time pointed to an internet-facing API endpoint that required **no authentication** and used sequential identifiers, so records could be enumerated one after another. Two of the most basic rules, broken at once.

</Story>

The caller is authenticated and has the right scope, but scopes say what _kind_ of thing you can do, not _which objects_. Every object access needs an ownership/permission check. This is BOLA, the #1 API security risk.

</Quiz>

<Takeaways>

- **Authentication** (<Status code={401} />) then **authorization** (<Status code={403} />/<Status code={404} />).
- OAuth 2.0 bearer tokens with well-named, least-privilege **scopes**.
- Check permissions **per object**, not just per endpoint (BOLA!).
- Allow-list writable fields; enforce limits; keep secrets out of URLs.

</Takeaways>
