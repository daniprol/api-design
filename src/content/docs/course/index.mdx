The course is designed to be read **in order**: each module builds on the vocabulary of the previous one. But every lesson also stands on its own, so feel free to jump straight to whatever is bugging you at work today.

<CourseMap />

## How the modules fit together

| #   | Module               | The question it answers                                            |
| --- | -------------------- | ------------------------------------------------------------------ |
| 1   | Foundations          | Why does API design matter, and what does "RESTful" really mean?   |
| 2   | Resources & URLs     | What are the _things_ in my API, and how do I name them?           |
| 3   | Speaking HTTP        | How do I use methods, status codes, errors and headers properly?   |
| 4   | Payloads & Data      | What should my JSON look like?                                     |
| 5   | Collections at Scale | How do I serve thousands of items quickly?                         |
| 6   | Robustness           | What happens with retries, concurrent edits and slow work?         |
| 7   | Evolution            | How do I change an API without breaking the people who use it?     |
| 8   | Production Ready     | How do I secure, document and operate it?                          |
| 9   | Event-Driven APIs    | What if my API needs to _push_ information instead of being asked? |
