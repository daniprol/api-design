<Hook>

Alice and Bob both open the same product in the admin tool. Alice fixes the price. Bob fixes a typo in the description and hits Save, sending the whole product, with the **old price**. Alice's fix silently disappears. Nobody gets an error. This is the **lost update** problem, and it's surprisingly common.

</Hook>

## The lost update, step by step

```text
Alice: GET  /products/1   → { price: 10, description: "Shoos" }
Bob:   GET  /products/1   → { price: 10, description: "Shoos" }
Alice: PUT  /products/1   ← { price: 12, description: "Shoos" }   ✅
Bob:   PUT  /products/1   ← { price: 10, description: "Shoes" }   ✅ 😱 price back to 10
```

## Pessimistic vs. optimistic

- **Pessimistic locking**: "I'm editing this, nobody else may touch it." Needs lock management, timeouts, "who locked this and went to lunch?". Rarely a good fit for HTTP.
- **Optimistic locking**: "Everyone may edit, but a write only succeeds if the resource hasn't changed since you read it." Conflicts are rare, so this is usually the right trade-off.

## ETag + If-Match

HTTP has optimistic locking built in. The server sends a version fingerprint (`ETag`); the client sends it back with `If-Match` when writing. If it no longer matches, the server refuses with <Status code={412} />.

```http
GET /products/1
→ 200 OK
  ETag: "v7"

PUT /products/1
If-Match: "v7"
{ "price": 10, "description": "Shoes" }

→ 412 Precondition Failed      # someone else changed it (now "v8")
```

Bob's client can now reload, show him the conflict, and let him re-apply his change. No silent data loss.

```python
@app.get("/products/{pid}")
def get_product(pid: str, response: Response) -> Product:
    product = repo.get(pid) or raise_404()
    response.headers["ETag"] = f'"{product.version}"'
    return product

@app.put("/products/{pid}")
def replace_product(pid: str, body: ProductIn,
                    if_match: Annotated[str | None, Header()] = None,
                    response: Response = None) -> Product:
    if if_match is None:
        raise Problem(428, "This endpoint requires an If-Match header")
    expected = int(if_match.strip('"'))
    # Atomic compare-and-set in the database:
    # UPDATE products SET ..., version = version + 1 WHERE id = :pid AND version = :expected
    updated = repo.update_if_version(pid, body, expected_version=expected)
    if updated is None:
        raise Problem(412, "The product was modified by someone else. Reload and try again.")
    response.headers["ETag"] = f'"{updated.version}"'
    return updated
```

<TabItem label="Django" icon="seti:python">

```python
from django.db.models import F

class ProductDetail(APIView):
    def get(self, request, pk):
        product = get_object_or_404(Product, pk=pk)
        return Response(ProductSerializer(product).data, headers={"ETag": f'"{product.version}"'})

    def put(self, request, pk):
        if_match = request.headers.get("If-Match")
        if not if_match:
            return problem(428, "This endpoint requires an If-Match header")
        serializer = ProductSerializer(data=request.data)
        serializer.is_valid(raise_exception=True)

        # compare-and-set: only update if the version is still the one the client saw
        updated = Product.objects.filter(pk=pk, version=int(if_match.strip('"'))).update(
            **serializer.validated_data, version=F("version") + 1
        )
        if not updated:
            return problem(412, "The product was modified by someone else.")
        product = Product.objects.get(pk=pk)
        return Response(ProductSerializer(product).data, headers={"ETag": f'"{product.version}"'})
```

```ts
app.put("/products/:id", zValidator("json", ProductIn), async (c) => {
  const ifMatch = c.req.header("If-Match");
  if (!ifMatch) return c.json({ title: "If-Match header required" }, 428);

  // UPDATE ... WHERE id = $1 AND version = $2 RETURNING *
  const updated = await repo.updateIfVersion(
    c.req.param("id"),
    c.req.valid("json"),
    Number(ifMatch.replaceAll('"', "")),
  );
  if (!updated) return c.json({ title: "Modified by someone else. Reload and retry." }, 412);

  c.header("ETag", `"${updated.version}"`);
  return c.json(updated);
});
```

:::caution[Check-then-write is not enough]
Reading the version, comparing it in your code, and _then_ writing has a race window. The comparison must be part of the **same atomic operation** as the write: `UPDATE … WHERE version = ?`, a transaction with `SELECT … FOR UPDATE`, or a conditional write in your datastore.
:::

## Alternatives to ETags

| Approach                                | How                                       | Notes                                       |
| --------------------------------------- | ----------------------------------------- | ------------------------------------------- |
| `ETag` / `If-Match`                     | Headers                                   | The HTTP-native way. Works with caches too. |
| Version in the body                     | `{"version": 7, ...}` sent back on update | Simple, visible, easy for clients.          |
| `Last-Modified` / `If-Unmodified-Since` | Timestamps                                | Only second precision: risky.               |

## Bonus: making the precondition mandatory

If a client forgets `If-Match`, you're back to lost updates. For sensitive resources, require it and respond <Status code={428} /> (Precondition Required) when it's missing.

<Do>

```http
PATCH /documents/9

```

Writes say which version they are based on.

</Do>
<Dont>

```http

```

Last write wins, silently overwriting whatever happened in between.

<Story kind="fun-fact" title="Wikipedia's edit conflicts">

Wikipedia is a giant optimistic locking system. When you open an article for editing, MediaWiki remembers which revision you started from. If someone else saves first, you get the famous **"Edit conflict"** screen, showing both versions so you can merge them by hand. No locks, millions of editors, and conflicts are rare enough that it works.

</Story>

<Takeaways>

- Concurrent full updates cause **silent lost updates**.
- Optimistic locking: write succeeds only if the version is unchanged.
- `ETag` on read, `If-Match` on write, <Status code={412} /> on mismatch, <Status code={428} /> if required but missing.
- The version check must be **atomic** with the write.

</Takeaways>
