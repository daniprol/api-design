<Hook title="What you'll get out of this">

By the end of this course, you'll be able to look at any HTTP API and say _exactly_ what's good about it, what's risky, and how you'd fix it, with the vocabulary and the references to back it up. And you'll design your own APIs with the instincts of someone who's seen a lot of them break.

</Hook>

## How the course is organized

The course has **9 modules** that build on each other, from mindset to events:

1. **Foundations**: why API design matters, API first, and what REST really means.
2. **Resources & URLs**: modelling your domain as things with good names.
3. **Speaking HTTP**: methods, status codes, errors and headers.
4. **Payloads & Data**: JSON conventions, `null`, dates, money.
5. **Collections at Scale**: pagination, querying and caching.
6. **Robustness**: retries, concurrent edits, slow work and rate limits.
7. **Evolution**: compatibility, versioning and deprecation.
8. **Production Ready**: security, links and operations.
9. **Event-Driven APIs**: when your API speaks first.

Each lesson takes about **7 to 10 minutes**. Do one with your morning coffee. ☕

## Where the material comes from

The concepts are grounded in the [Zalando RESTful API Guidelines](https://opensource.zalando.com/restful-api-guidelines/), one of the most thorough public API style guides, plus HTTP RFCs and real-world API practice. The structure is a general course, not a walkthrough of one company's rules. [Company guides](/guides/) compares how different companies decide, and more (Google AIP first) are on the way.
